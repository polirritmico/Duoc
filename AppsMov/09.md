# Clase 09: Validaciones

Un formulario tiene muchos campos. La idea de la validación es que los usuarios
no ingresen datos incorrectos y detectarlos antes siquiera de enviarlos al back.

```kotlin
fun OutlinedTextfield() {
  value = uiState.nombre,
  onValueChange = {
    viewModel.onNombreChange(it)
    isError = uiState.errores.nombre != null,
    supportingText = {
        if (uiState.errors.nombre != nul) {
          Text(text = uiSatte.errores.nombre!!, color = MAterialTheme.colorScheme.error)
        },
      }
  },
  { label = { Text("Nombre") } },
}
```

## Flujo de datos

El viewmodel recibe la interacción, ejecuta la lógica de validación y procesa el
nuebo estado.

Modelo (dataclass) contiene el estado actual inmutable del formulario y sus
errores.

Vista(@Composable) El usuario interactúa. Observa los cambios mediante
collectAsState()

---

## Paso 1: Definir los modelos de datos

El modelo centraliza todos los campos y sus posibles errores en una única fuente
de a verdad inmutable.

```kotlin
data class FormularioUiState(
  val nombre: String = "",
  val correo: String = "",
  val telefono: String = "",
  val terminosAceptados: Boolean = false,
  val errores: FormularioErrores = FormularioErrors();
  val esValido: Boolean = false,
)

data class FormularioErrors(
  val nombre: String? = null,
  val correo: String? = null,
  val telefono: String? = null,
)
```

## Paso 2: Encapsulación con StateFlow

El ViewModel necesita crear un StateFlow del modelo. Aquí va la lógica de
negocio. No se edita directamente los valores en el modelo, sino se utiliza el
ViewModel.

## Paso 3: Reactividad en tiempo real
